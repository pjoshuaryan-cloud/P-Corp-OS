- **Decided (`TECH_STACK.md`): platform scope is Apple-only (macOS desktop, iOS companion); desktop UI shell is native SwiftUI**, chosen over Electron and Tauri for native feel and direct code/pattern reuse with the iOS companion. - **Decided (`TECH_STACK.md`): Frank's backend runs in Python**, via the Claude Agent SDK, communicating with the SwiftUI shell over local IPC. Chosen primarily because Trading Division is the flagged likely first specialized agent and the existing trading-robot repo's analysis tooling is already Python (135 `.py` files vs. 19 `.mq5` files, confirmed today) — direct reuse over a second implementation.
- **Decided (`TECH_STACK.md`): IPC mechanism is local HTTP + WebSocket (FastAPI), bound to `127.0.0.1` with a local auth token** — REST for simple calls, WebSocket for streaming responses and unprompted push notifications. Chosen over XPC/Unix sockets (both local-only, would need rebuilding for mobile/remote sync) and gRPC (protobuf schema overhead across Swift/Python not justified at this scale), specifically because the same interface can later be exposed for remote/mobile access behind real auth and TLS rather than requiring a separate integration.
- **Decided (`TECH_STACK.md`): process lifecycle target is a persistent background service managed via `SMAppService`**, not a subprocess tied to the app's lifetime — because Frank's "second brain" framing and Layer 1's Notifications responsibility require Frank to exist and act even when the UI is closed. Early prototyping may still use a simple spawned subprocess for dev-iteration speed; graduating to `SMAppService` is a sequencing detail, not a change of target.
