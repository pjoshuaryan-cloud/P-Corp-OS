- **Decided (`TECH_STACK.md`): IPC mechanism is local HTTP + WebSocket (FastAPI), bound to `127.0.0.1` with a local auth token** — REST for simple calls, WebSocket for streaming responses and unprompted push notifications. Chosen over XPC/Unix sockets (both local-only, would need rebuilding for mobile/remote sync) and gRPC (protobuf schema overhead across Swift/Python not justified at this scale), specifically because the same interface can later be exposed for remote/mobile access behind real auth and TLS rather than requiring a separate integration.
- **Decided (`TECH_STACK.md`): process lifecycle target is a persistent background service managed via `SMAppService`**, not a subprocess tied to the app's lifetime — because Frank's "second brain" framing and Layer 1's Notifications responsibility require Frank to exist and act even when the UI is closed. Early prototyping may still use a simple spawned subprocess for dev-iteration speed; graduating to `SMAppService` is a sequencing detail, not a change of target.
- **Decided (`TECH_STACK.md`): packaging is an embedded, relocatable Python runtime + locked dependencies as bundled resources, launched via a thin native shim executable** — not a PyInstaller/py2app frozen single-binary. Chosen because per-dylib notarization signing gets increasingly fragile under frozen-binary tooling as dependencies grow (numpy/pandas for Trading Division, etc.), and owning the embedding directly avoids inheriting that fragility over a decade-long horizon.
- **Decided (`TECH_STACK.md`): database is SQLite, embedded locally in the Python backend**, for tasks, projects, conversations, and memory records, with a semantic/vector search layer on top for contextual recall rather than a dedicated vector DB as the primary store. Chosen over Postgres specifically to avoid pre-deciding the still-open self-hosted-vs-cloud sync question — SQLite works local-first today and doesn't foreclose a sync layer (e.g. libSQL/Turso) being added later without a storage migration.
- **Decided (`TECH_STACK.md`): sync is libSQL/`sqld`, starting on Turso's managed offering, with self-hosting `sqld` kept as an explicit reversible future option** — not a hard self-hosted-vs-managed fork today. Chosen over a Mac-as-server/Tailscale-tunnel model (Frank would go dark whenever the Mac is closed or offline) and over committing to full self-hosting now (real ops/security burden competing with the trading robot and Alpha Mode for founder time). Because `sqld` is open source and Turso speaks the same protocol as a self-hosted instance, "who hosts it" can be revisited later without a data-model or protocol rewrite. Flags an encryption-at-rest requirement for the most sensitive memory categories (marriage, family, health) as a `SECURITY.md` follow-up.

Chosen because P Corp OS has exactly one user ever, so the real problem is device trust for a handful of Joshua's own devices, not multi-tenant user management; a managed auth provider would put an external company in the critical path of accessing his own second brain. Reuses the Apple platform bet already made and subsumes the existing local loopback auth token into one mechanism. **This closes out the core `TECH_STACK.md` decision set** — only iOS companion specifics remain open, and can wait until real iOS work begins.
